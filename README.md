### Pythonの命名規則（PEP 8）
Pythonには「PEP 8」と呼ばれる公式のコーディング規約があり、誰が読んでも分かりやすいコードにするための明確な命名ルールが存在する。
（※ルールから外れてもエラーにはならないが、Pythonコミュニティの共通言語として守るのが基本）

- **パッケージ・モジュール**
  - ルール: すべて小文字。できるだけ短くする。
  - 例: `mypackage`, `date_utils.py`

- **クラス**
  - ルール: CapWords（パスカルケース）。各単語の先頭を大文字にし、アンダースコアは使わない。
  - 例: `UserProfile`, `MyClass`

- **変数・関数（メソッド）**
  - ルール: スネークケース。すべて小文字にし、単語の区切りにアンダースコア（`_`）を使う。
  - 例: `user_name`, `calculate_total()`

- **定数**
  - ルール: アッパースネークケース。すべて大文字にし、単語の区切りにアンダースコアを使う。
  - 例: `MAX_COUNT`, `TAX_RATE`

  * *ファイル構成とクラスルールの違い*:
    * Java: 「1ファイルにつき public クラスは1つ」「ファイル名とクラス名は完全に一致させる」という厳格な縛りがある。
    * Python: 上記の縛りがなく、関連する親クラスと子クラスを1つのファイルにまとめて身軽に記述できる（1ファイル＝1モジュールという思想）。
  * *カプセル化の思想の違い*:
    * Java: private キーワードによってコンパイラレベルで厳格にアクセスを弾く。
    * Python: アクセス修飾子が存在せず、アンダースコア（__）による命名規則で「直接触らないでほしい」という意図を示す「開発者間の紳士協定」的な文化がある。
  * *直感的なプロパティアクセス*:
    * Java: getWeight() や setWeight(4.1) のように明示的にメソッドを呼び出す。
    * Python: @property を使うことで、外部からは tama.weight = 4.1 と単なる変数への代入に見えるのに、裏ではしっかりセッターのバリデーション処理が走る。TypeScriptの get / set と非常に似た感覚で直感的に扱える。
  * *オーバーライドの仕様*:
    * Java: @Override アノテーションを付与して明示する。
    * Python: アノテーションは不要で、単に同じ名前のメソッドを定義するだけで上書きされる。スッキリ書ける反面、メソッド名をタイポすると別の新規メソッドとして扱われてしまうため注意が必要。
  * *自身のインスタンスを指すキーワード*:
    * Java: this を使い、省略できることも多い。
    * Python: クラス内のメソッドでは、必ず第一引数に self を明記する必要がある（メソッド呼び出し時には自動で渡されるため引数には書かない）。
