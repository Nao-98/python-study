### Pythonの命名規則（PEP 8）
Pythonには「PEP 8」と呼ばれる公式のコーディング規約があり、誰が読んでも分かりやすいコードにするための明確な命名ルールが存在する。
（※ルールから外れてもエラーにはならないが、Pythonコミュニティの共通言語として守るのが基本）

- **パッケージ・モジュール**
  - ルール: すべて小文字。できるだけ短くする。
  - 例: `mypackage`, `date_utils.py`

- **クラス**
  - ルール: CapWords（パスカルケース）。各単語の先頭を大文字にし、アンダースコアは使わない。
  - 例: `UserProfile`, `MyClass`

- **変数・関数（メソッド）**
  - ルール: スネークケース。すべて小文字にし、単語の区切りにアンダースコア（`_`）を使う。
  - 例: `user_name`, `calculate_total()`

- **定数**
  - ルール: アッパースネークケース。すべて大文字にし、単語の区切りにアンダースコアを使う。
  - 例: `MAX_COUNT`, `TAX_RATE`

* **気づき・他言語との違い**:
  * *Javaとの違い*:
    * 型とセミコロンが消滅: String name = "たま"; ではなく、単に name = "たま" と書く。行末の ; も不要。
    * カッコ {} が消滅: if や for のブロックは {} ではなく、「インデント（半角スペース4つ）」だけで表現する。インデントがずれるとエラーになる。
    * おまじないが消滅: public class... や public static void main... は一切不要。1行目からいきなり処理を書けばそのまま動く。
    * 自動で src フォルダを生成するような機能や、厳格なディレクトリ構成の強制ルールがない。
    
  * *ブロック（スコープ）の表現*:
    * *Java*: 中括弧 `{ }` で処理のまとまりを囲む。
    * *Python*: 中括弧は使わず、コロン `:` と **インデント（通常は半角スペース4つ）** のみで処理のまとまりを表現する。インデントがずれるとエラーになる。
  * *文字列の組み立て*
    * *Java*: `+` 演算子で文字列と変数を結合することが多い。
    * *Python*: f文字列（`f"{変数}"`）を使うのが主流。型変換を気にせず直接埋め込めるため、コードがスッキリする。
  * *リスト（配列）と繰り返し*:
    * *Java*: 配列の宣言には `{ }` を使い、リスト操作には `ArrayList` などの型の宣言が必要。
    * *Python*: `[ ]` だけで簡単にリストを作成でき、変数の型宣言も不要。
    * Pythonの `for item in list:` は、Javaの拡張for文（`for (String item : list)`）と非常に似た感覚で扱えるため馴染みやすい。
